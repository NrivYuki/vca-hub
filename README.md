# vca-hub

眼鏡店・ラボの機器と PC の間で、VCA(DCS v3.14)のデータを受け取り、保存し、加工機・別の PC・共有フォルダへ中継する常駐プログラムである。

- 受け取った原文は変えずに保存する(個人情報の項目を除く設定のときは、除いたものを保存する)。送るときは、送り先に合わせて入れ物を組み立て直す。レコードの値は変えず、足りない項目を推測で埋めない。ただし、規格が求める形にそろえるもの・送らないものがある(送らないもの: サグ・注記(REM)・送り手の名乗り・機器ごとの値の行。置き換えるもの: 機器ごとの値、反転した玉型の寸法。足すもの: DO が無いときの加工するレンズ)。これらは送る前の確認に出す。
- 受け取ったデータは、管理画面で人が名前を付けるまで、どこへも渡さない。名前は、送り先へのジョブ番号になる。
- 加工条件の追加や、メーカー独自の項目・通信方式への対応は、拡張で行う。

設計の詳しい内容は [docs/design.md](docs/design.md) にある。

## 必要なもの

- Windows(主な対象)
- Node.js 22 以上。配る zip には node.exe を同梱するので、zip から使うときは要らない。

外部のパッケージは使わない。

## 起動

`start.bat` を開く。または、次のコマンドで起動する。

```
npm start
```

送受信の記録は、窓には出さず、管理画面の「記録」と `data/log/` に残す。管理画面は、この PC のブラウザで http://localhost:8765 を開く。管理画面は、この PC からだけ開ける。止めるときは、窓を閉じるか Ctrl+C を押す。

## 設定

設定は `config.json` に書く。書かなかった項目は既定値のままになる。形や値の範囲に誤りがあれば、項目の名前を出して起動しない。相対のパスは vca-hub のフォルダを基準にする。1 つのデータのフォルダ(`dataDir`)を使えるのは 1 つの vca-hub だけで、2 つ目は起動しない。この確かめは同じ PC の中だけで働くので、`dataDir` を共有フォルダに置いて 2 台の PC から使わない(2 台の vca-hub が互いに索引を上書きする)。主な項目は次のとおりである。

| 項目 | 中身 | 既定値 |
|---|---|---|
| `remote` | 機器から接続してくる形(リモート接続)の待ち受け: `{ "enabled": true, "port": 33512 }` | 有効、ポート 33512 |
| `local` | vca-hub から機器へ接続する形(ローカル接続)の相手: `[{ name, host, port }]`(`host` は IP アドレス) | なし |
| `autoconnect` | 機器が UDP で知らせてくる形(オートコネクト): `{ "enabled": false, "port": 33511 }` | 無効、ポート 33511 |
| `destinations` | 別の PC やソフトへの送り先: `[{ name, host, port, type: 'UPL' か 'TRC', protocol }]` | なし |
| `listeners` | 追加の待ち受け: `[{ name, port, protocol, settings }]` | なし |
| `allow` | 接続を受け付ける IP アドレスと、ローカル接続の相手の範囲(`192.168.0.0/16`・`fd00::/8`・`10.1.2.3` の形)。形の正しくない項目があれば起動しない。機器のアドレスを書き足して使う | この PC だけ |
| `connections` | 待ち受けとオートコネクトで同時に開いておける接続の数: `{ total, perAddress }`(全体と、相手の IP ごと)。超えた接続は断って記録に残す。0 は上限なし | 全体 64、IP ごとに 8 |
| `exportDir`・`importDir` | 共有フォルダへの書き出し先と、取り込むフォルダ | なし |
| `removePII` | 受け取ったときに、装用者の氏名・年齢などの項目を除いて保存する | 有効 |
| `retentionDays` | 保存期間(日)。過ぎた受信データ(送信待ちのものを除く)、送受信の記録、取り込んだ元のファイルを自動で消す。`null` で無期限(0 や文字列は誤りとして起動しない) | 90 日 |
| `web` | 管理画面のポート。待ち受けるアドレス(`host`)は、この PC のもの(`127.0.0.1`・`::1`・`localhost`)だけにできる | 8765 |
| `dataDir` | データの保存先 | `data/` |
| `extensions`・`extensionsDir` | 使う拡張(`{ "名前": true }`)と、拡張を置くフォルダ | なし、`extensions/` |

例:

```json
{
  "remote": { "enabled": true, "port": 33512 },
  "local": [{ "name": "加工機 1", "host": "192.168.0.50", "port": 50000 }],
  "destinations": [{ "name": "ラボ", "host": "192.168.0.10", "port": 33512, "type": "UPL" }],
  "allow": ["127.0.0.1/32", "192.168.0.0/16"],
  "exportDir": "\\\\server\\share\\vca-out"
}
```

ほかの機器から vca-hub へ接続する形(リモート接続・オートコネクト)を使うときは、Windows のファイアウォールで node.exe の受信を許可する必要がある。配る zip には、許可を登録する `firewall.bat`(管理者として 1 回だけ実行する)を入れている。許可するのは「プライベート」と「ドメイン」のネットワークだけである。Windows がネットワークを「パブリック」に分類していると許可が効かないので、そのときはネットワークの種類を「プライベート」に変える。`firewall.bat` は、vca-hub を初めて起動する前に実行する(先に起動して Windows の警告を「キャンセル」すると、node.exe を遮断する規則ができ、許可より優先される)。許可するポートは、既定のリモート接続(33512)とオートコネクト(33511)だけである。ポートを変えたときや、追加の待ち受け(`listeners`)を使うときは、そのポートの許可を自分で足す。リポジトリから `start.bat` や `npm start` で動かすときは `firewall.bat` が無いので、初めて起動したときの Windows の警告で「プライベート ネットワーク」を選んで「アクセスを許可する」を押すか、Windows Defender ファイアウォールの設定で、使っている node.exe の受信を許可する。

## 前の版から更新するとき

- 機器の側には、この PC の IP アドレス(コマンドプロンプトで `ipconfig` を実行し、「IPv4 アドレス」を見る)と、リモート接続のポート(既定 33512)を設定する。機器の説明書で、機器が「ホストへ接続する」(ホストのアドレスを入れる欄がある)なら `remote` で受ける。`local` は、機器が待ち受けていて、vca-hub から接続するときだけ書く(例の `local` の「加工機 1」は、使わなければ消す)
- 許可範囲(`allow`)の既定は、この PC だけである。機器のアドレスを `allow` に書き足す。書かないと、ほかの機器からの接続を断り(記録に残す)、`local` に書いた相手が範囲の外なら起動しない
- 保存期間(`retentionDays`)の既定は 90 日である。書いていなければ、更新した後の最初の起動で、90 日より古い受信データ(送信待ちのものを除く)・記録・取り込んだ元のファイルを消す。残したいときは、先に `retentionDays` を書く(`null` で無期限)
- `config.json` の書き方の誤り(知らない項目の名前を含む)があると、項目の名前を出して起動しない

## データと個人情報

受け取ったデータは `data/` に保存する。受け取った原文は、手を加えずにそのまま残す(個人情報の項目を除く設定のときは、除いたものを残す)。送受信の記録には、ジョブ番号・相手・結果だけを書き、レコードの中身は書かない。個人情報の項目として除くのは、装用者の氏名・年齢などの項目(表 A.1 で装用者の項目とされるもの)と口座番号で、処方度数、レンズに刻む文字、注記、`_` で始まる独自の項目は除かない(詳しくは docs/design.md 7 章)。取り込むファイルの名前も、装用者の名前のことがあるので気を付ける。ジョブ番号(`JOB`)は除かず、保存するファイルの名前と送受信の記録に入るので、装用者の名前をジョブ番号にしない。規格に無い項目(`PATIENT=` など)も除かない。

受信データ、送受信の記録(`data/log/`)、共有フォルダから取り込んだ元のファイル(「取り込み済み」「取り込めなかった」のフォルダ)は、既定では 90 日で消す(`retentionDays`)。取り込んだ元のファイルは、個人情報の項目を除く前のものである。ほかのソフトが開いていて消せなかったファイルは、1 時間ごとに消し直す(起動し直しても続ける)。保存期間を 30 日より多く過ぎた受信データは、受け取ったときに PC の時計が遅れていたかもしれないので自動では消さず、記録に件数を出す。管理画面で確かめて消す。

vca-hub が消すのは、`data/` と取り込むフォルダの中のファイルと、書き出し先に vca-hub が残した書きかけの一時ファイルだけである。バックアップ、Windows のシャドウコピー(以前のバージョン)、OneDrive などの同期、共有フォルダへ書き出したファイルとその先の複製は、vca-hub からは消せない。これらに残る個人情報は、利用者が別に管理する。

VCA の注文データには、装用者の氏名や処方度数などの個人情報が含まれることがある。データの保存先のフォルダは、vca-hub を使う Windows のアカウントだけが読み書きできるようにすることを勧める。共有フォルダへ書き出すときは、書き出し先を誰が読めるかを利用者が管理する。

## 拡張

拡張は `extensions/<名前>/index.js` に置き、`config.json` の `extensions` に名前を書く。書いたものだけを読み込む。拡張は vca-hub と同じ権限で動くので、中身を確かめたものだけを入れる。

例を `examples/extensions/` に置いている。

| 例 | 中身 |
|---|---|
| `processing-conditions` | 加工条件を、加工機への応答と、共有フォルダ・送り先へのデータに入れる。設定 `required: true` で、条件を付けるまで送れないようにする |
| `vendor-records` | 機器ごとに項目を足したり外したりする |
| `text-protocol` | DCS ではない、テキストの通信方式で受け取り、送る |

拡張の仕組み(フック・通信方式・管理画面のページ)は、設計書の 13 章にある。拡張で通信方式を足した例として、マイコン向けの通信規格 OLDP の機器をつなぐ拡張を [vca-hub-extension](https://github.com/NrivYuki/vca-hub-extension) に置いている。

## テスト

```
npm test
```

模擬機器(`tools/mock-tracer.js`・`tools/mock-edger.js`)で、受信から加工機への送信までを手で試せる。

`npm test` のほかに、次の道具で、壊れた入力や異常な止まり方に対する動きを確かめる(どれも一時フォルダのデータで動かす)。

| 道具 | 確かめること |
|---|---|
| `tools/check-xss.js` | 受け取ったデータ(JOB・玉型の形式の欄・項目の値・機器の名乗り)の HTML が、管理画面でスクリプトとして動かないこと。ヘッドレスの Chrome か Edge を使う(`npm test` でも、ブラウザがあれば動かす) |
| `tools/fuzz-vca.js` | VCA の口(リモート接続・オートコネクト)と共有フォルダの取り込みに、壊れた入力を送っても止まらないこと、メモリを使い続けないこと、許可範囲の外へつなぎに行かないこと、1 つの相手が接続を多く開いても IP ごとの上限までしか受けないこと、同時のアップロードで索引が崩れないこと |
| `tools/fuzz-web.js` | 管理画面の口に、壊れたパス・本文を送っても止まらず、500 を返さず、拡張のフォルダの外のファイルを返さないこと |
| `tools/crash-store.js` | アップロードの途中で強制終了しても、索引が読め、索引の全ての記録にファイルがあり、起動し直して受けられること |

```
node tools/fuzz-vca.js
node tools/fuzz-web.js
node tools/crash-store.js 40
```

## 配る zip を作る

```
pwsh -File tools/package.ps1 -NodeZip <Node.js の公式の Windows 用 zip>
```

`dist/` に、node.exe を同梱した zip ができる。展開して `start.bat` を開くだけで動き、インストールも管理者の権限も要らない。

## ライブラリ

`src/lib/` の `vca-parser.js`・`vca-records.js`・`vca-session.js`・`vca-tcp.js` は、[vca-guide](https://github.com/NrivYuki/vca-guide) の `src` から写したものである。vca-guide と同じものに保ち、vca-hub の中では書き換えない。写した元(vca-guide のコミット)と各ファイルの SHA-256 を `src/lib/vca-guide.json` に残し、テスト `tests/e2e.test.js` が、写したときのままであることを確かめる。vca-guide が隣のフォルダ(`../vca-guide`)にあれば、同じであることも確かめる。写し直したときは、`vca-guide.json` も書き直す。

## 注意

- 実機(トレーサー・加工機)では確かめていない。確かめた範囲は、設計書の 10 章にある。
- ホストによっては、大きいデータのパケット(例: 両眼 1440 点の形式 1 の玉型。約 15 KB)を受けられないことがある。DCS Host Simulator は約 12 KB を超えるデータのパケットを受け取らなかった(設計書の 11 章)。
- DCS v3.14 に従って作っているが、規格への準拠は保証しない。
- vca-hub は加工用のデータを中継するだけで、診断や処方の決定は行わない。
